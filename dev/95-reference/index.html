ModuleMixins.substitute_top_level — Method
substitute_top_level(var, val, mod, expr)

Takes a syntax object expr and substitutes every occurence of module var for val, only if the resulting object is actually present in module mod. The mod module should correspond with a lookup of val in the caller's namespace.

@for_each(M -> M.method(), lst::Vector{Symbol})

Calls method() for each module in lst that actually implements that method. Here lst should be a vector of symbols that are all in the current module's namespace.

pass(x::CompositePass, expr)

Tries all passes in a composite pass in order, and returns with the first that succeeds (i.e. doesn't return no_match). You may create a CompositePass by adding passes with the + operator.

ModuleMixins.Passes.pass — Method
pass(x::Pass, expr)

Interface. An implementation of the pass function should take a Pass object and an expression (or symbol), and return no_match if the expression did not match the pattern.

You can use the given Pass object to store information about this pass, return syntax that should replace the current expression, or nothing if it should be removed.

ModuleMixins.Common.strip_syntax_version — Method
strip_syntax_version(expr)

From Julia 1.14, a module expression may carry the syntax version of the code it was parsed from as its first argument: Expr(:module, v"1.14.0", true, name, body). Whether it does depends on the project the code lives in, not on the Julia version alone. Remove the version, so that @capture patterns of the form module name_ body__ end match either way.

ModuleMixins.Procedural.Composite — Type
Composite{T <: Tuple, R <: Tuple}

A value composed of parts, one per component. Properties are forwarded to the part that has a field of that name, so c.x works for any field x of any part. R is a tuple of RoleMap markers, recording which part fills each role.

ModuleMixins.Procedural.record_type — Method
record_type(name::Symbol, roots::Module...; parameters...)

The Composite type of record name, for the closure of roots. It has one part for every component that defines a type name, in dependency order.

A type parameter of a part that is named after a record is filled with the composite type of that record. Any other type parameter is taken from parameters, by name.

ModuleMixins.Syntactic.@component — Macro
@component module Name
    [@mixin Components...]
    [@requires Requirements...]
    [@implements Roles...]
    ...
end

Define a component module. The declarations expand into methods of ModuleMixins.Procedural:

  • @mixin A, B: import A and B from the parent module (if they are plain names), and require them as components.
  • @requires R: require role or component R.
  • @implements R: the component implements role R.

If a field type of a struct mentions another struct S of the same module, the struct gets a type parameter S, which record_type fills with the composite of all parts of record S.
